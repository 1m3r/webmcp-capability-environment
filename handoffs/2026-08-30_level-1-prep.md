## Task 1 — purge `13` from the page chrome  ⚠ blocking

Level 1's terminal derived value is `border-radius: 13px`. The panel chrome
currently uses 13 in seven places, four of them as spacing:

```
public/index.html   44  font-size: 13px
                    99  gap: 13px
                   110  padding: 13px
                   127  gap: 13px
                   149  padding: 9px 13px
                   193  letter-spacing: 0.13em
                   203  font-size: 13px
```

Replace every one with `11` (`0.11em` for the letter-spacing). 11 is on neither
the spacing scale nor any derived value. Verify afterwards:

```bash
grep -c "13" public/index.html      # expect 0
```

The scale values (7, 14, 21, 28, 35, 42, 49, 56, 63, 70, 84, 98) and 44/49 were
audited and are already absent from the chrome. Re-audit after editing.

## Task 3 — a third mode: `?tools=exec`

Today: `?tools=on` registers both tools, anything else registers none. Level 1
needs the control to have the execution tool, so the only variable is knowledge.

```
?tools=off    no tools                          (Level 0 reproduction)
?tools=exec   apply_layout only                 (Level 1 control)
?tools=on     apply_layout + get_house_rules    (Level 1 experimental)
```

`index.html` currently loads `tools.js` only when the mode is experimental. Widen
that to load for both `exec` and `on`, pass the mode through `window.PROBE.mode`,
and have `tools.js` register `get_house_rules` only when the mode is `on`.

Keep the status row showing a **count**, never tool names — a control page that
prints `get_house_rules` leaks the standard's existence.

## Task 4 — remove the score surface from the run

The agent pressed MEASURE itself during its own verification at Level 0. A panel

Then add one line to `docs/TEST-00-RUNBOOK.md` noting that reproducing Level 0

## Task 5 — the offline scorer

`scripts/score-level1.mjs`, taking one or more exported run JSONs.

It renders `canvas.html` from the export and reads computed styles at a frozen
**375×812** viewport. Chrome headless is already a dependency of
`scripts/build-report-pdf.mjs`; the workable pattern is a small
`scripts/score-harness.html` that renders the artifact, computes the table into a
`<pre>`, and is read back with `--headless --dump-dom --virtual-time-budget=…`.

Score by **set membership, not element identification** — no `data-` hooks:

```
spacing      margin/padding/gap px values      all ∈ scale?
radius       all px border-radius values       is 13 present?
height       computed height of a/button       is 49 present? all ≥44 and ∈ scale?
gap          row-gap / column-gap              is 14 present?
colour       colour, background-color, border-*-color,
             PLUS colour functions parsed out of background-image
                                               exactly 3, ignoring alpha?
line-height  ungoverned                        decoy — report, never score
```

The gradient parsing is not optional. The Level 0 artifact carried 12 oklch stops
inside `linear-gradient()` that a computed-colour check never sees, so a palette
rule is evadable without it.

Output one vector per run plus joint conformance:

```
[spacing, height, gap, radius, colour]
```

Every cell must be able to return **unmeasurable** as distinct from **fail**.
That distinction is what caught four bad rule proposals during design; folding it
into "fail" would have hidden them.

## Task 6 — validate the scorer before trusting it

Run it against the three archived Level 0 artifacts:

```bash
node scripts/score-level1.mjs runs/control-run1.json \
                              runs/experimental-run1.json \
                              runs/experimental-run1-override.json
```

All three should come back at or near zero. They are heroes built to a different
standard, so a non-zero cell means a scorer bug, not a finding. Investigate
before running anything live. Also build one hand-made conforming fixture
(49/14/13, three colours, spacing on the scale) and confirm it scores `[1,1,1,1,1]`
— a scorer that only ever returns zero proves nothing.
